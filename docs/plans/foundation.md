# Foundation plan

Remaining work from an empty SDK and a one-command tool to the first crates.io release and parallel service porting. The [architecture](../design/architecture.md) owns the contract and [workflow](../../instructions/workflow.md) owns how a task runs. Delete a task when it lands and this file when all of it has.

## Shared files

The primary is the integration owner of the workspace `Cargo.toml`, `Cargo.lock`, each crate's `Cargo.toml`, `crates/greennode-sdk/src/lib.rs`, `crates/greennode/src/cli.rs` and `src/services/mod.rs`, the `Makefile`, the workflows, and the AGENTS.md code map. A brief may hand a worker named lines or one named shared file for that task only; the brief says exactly which. The primary regenerates the lockfile when merging. A new shared type, or a change to one, lands before the tasks that depend on it.

## Order

Task 1 does not block code: SDK tasks write no doc comments until the owner approves the exception, and a later pass adds them; the baseline tag gates task 14. Task 2 started before it and is reworked if the review changes the projection rules. After 1: task 3, and task 4 once task 2 has landed. After 3: tasks 5, 6, and 7 in parallel. After 3, 4, and 7: task 8. After 5 and 6: task 9. After 8 and 9: task 10. After 10: task 11, then 12. Task 13 starts after 1 and lands before the first release. Task 14 starts when 11 lands.

## Tasks

- [ ] **1. Owner decisions.** The designs passed independent review. Two decisions remain the owner's: the baseline tag (`v1.0.1` or `v1.2.0`; a move updates the architecture's baseline section, the `Makefile` values, and the parity list, and adds a task to port the difference), and the exception that lets public SDK items carry `///` doc comments. Tasks that touch either wait for the answer.
- [ ] **2. Output formatter and goldens.** In progress. The Go-compatible JSON writer, the f64 value tree, the table and text renderers, escaping, and dynamic-map redaction, as [CLI output](../design/cli-output.md) specifies, tested against the baseline's 407 golden files. Owns `crates/greennode/src/cli/render.rs`, `src/cli/render/`, `tests/render.rs`, `tests/fixtures/render/`. Review (Sol). Rework after task 1 if the review changes the projection rules. Golden cases that need the query engine or a service-specific renderer are excluded with their reason, not forced through the generic formatter.
- [ ] **3. Shared contracts.** Implementer. The SDK's public shapes with no I/O behind them: the request context and cancellation, the clock, `Secret`, `Token`, the error class, error, failure, and write-dispatch types, the list and paged-list models, the configuration source trait, and the debug event types, as the [SDK design](../design/sdk.md) specifies. Owns `crates/greennode-sdk/src/context.rs`, `secret.rs`, `error.rs`, `model/`, `tests/core_contracts.rs`. Review (Sol) with canary tests for `Secret`.
- [ ] **4. Query engine.** Implementer. The port of go-jmespath v0.4.0 as [CLI query](../design/cli-query.md) specifies, over the value tree from task 2, with the library's compliance suite and committed differential fixtures. Owns `crates/greennode/src/cli/query.rs`, `src/cli/query/`, `tests/query.rs`, `tests/fixtures/query/`, `crates/greennode/licenses/go-jmespath-LICENSE`, and the license-notice lines in `scripts/comments-allowlist.txt`. Review (Sol).
- [ ] **5. Configuration.** Implementer. The INI reader, mode and path selection, the incomplete-pair refusal, file safety, the cache-path check, `Config::resolve_profile`, and the offline part of `Config::load` up to the chosen credential source, as the [configuration design](../design/config.md) specifies. Baseline: `internal/ini/`, `internal/core/load.go`, `internal/core/cdnkey.go`, `internal/cli/storage_object_profile.go`. Owns `crates/greennode-sdk/src/config/`, `tests/core_config.rs`, `tests/fixtures/core/config/`. Adversarial review (Sol) against the design's test table.
- [ ] **6. Connection and product sender.** Implementer. The private hyper-util client with the hyper-rustls connector, endpoint validation, and the product sender with its redirect, retry, bound, and event rules, plus the loopback test server, as the [request policies](../design/sdk-requests.md) specify. Baseline: `internal/transport/`, `internal/endpoints/`. Owns `crates/greennode-sdk/src/wire/connection.rs`, `wire/product/`, `src/endpoint/`, `tests/support/`, `tests/core_wire.rs`. Adversarial review (Sol).
- [ ] **7. CLI frame: declarations and parsing.** Implementer. The root, global flags, version, the operation declaration and registry, staged input with `--cli-input-json`, the hidden documentation generator, and the parity and shipped-command tests, with one toy service in tests only. Baseline: `internal/cli/root.go`, `op.go`, `flags.go`, `input.go`, `gendocs.go`. Owns `crates/greennode/src/cli/root.rs`, `op.rs`, `input.rs`, `gendocs.rs`, `tests/frame_parse.rs`, `tests/parity.rs`, `tests/parity/shipped-commands.json`. Review (Sol).
- [ ] **8. CLI frame: dispatch and errors.** Implementer. The dispatch phases and guards, the CLI adapter contract, output policies, the error classifier and exit codes with service-local rules, process injection and cancellation in `main.rs`, using the render and query modules. Baseline: `internal/cli/op.go`, `errors.go`, `errors_exit.go`, `cmd/vngcloud/main.go`. Owns `crates/greennode/src/main.rs`, `src/cli/dispatch.rs`, `errors.rs`, `tests/cli.rs`, `tests/frame_dispatch.rs`. Review (Sol).
- [ ] **9. Sign-in, cache, and discovery.** Four implementers on disjoint paths, then one adversarial review (Sol) of the whole with a canary for every secret. The token cache with its lock and one-time-code marker (`src/cache/`; baseline `internal/tokencache/`). The service-account exchange (`src/wire/credential/service_account.rs`; baseline `internal/core/service_account_*.go`). The IAM user sign-in with one-time codes (`src/wire/credential/iam_user.rs`; baseline `internal/iamuser/`). The session, provider contract, refresh gates, and project discovery (`src/session/`, `src/discovery/`; baseline `internal/core/`, `internal/discovery/`).
- [ ] **10. First reads end to end.** Implementer. Billing reads in the SDK and their commands in the tool, as the template every service follows, with the generated documentation page. The primary then updates [porting](../../instructions/porting.md) with the pattern and asks the owner to approve one read-only live run.
- [ ] **11. First guarded write and configure.** Two implementers in parallel, each with adversarial review (Sol). One: `billing create-budget`, `update-budget`, and `delete-budget`, proving send once, write dispatch, `--yes`, and read-only on real operations. Partial output is proven in task 8 with a frame fixture, since these budget operations return none on error. The other: `configure` with `set`, `get`, and `list`, the legacy-mode refusal, and the recheck under lock; baseline `internal/cli/configure*.go`, `configfile.go`.
- [ ] **12. First release.** The primary does the one-time GitHub setup. The owner approves the `v0.1.0` tag and publishes both crates by hand as the [release design](../design/release.md) describes, then adds the two Trusted Publishers.
- [ ] **13. Release tooling.** Implementer, handed `.github/workflows/release.yml`, `publish-crates.yml`, and the release lines of the `Makefile` for this task. The release checker with its receipt and registry-state commands, the checksum-checking credential helper, the manifest gate, the shipped-command gate, and their tests, ported from duolane and extended for two crates as the [release design](../design/release.md#implementation-boundary) lists. Adversarial review (Sol). Accept: the loopback-registry test in the design's unverified list passes on macOS and Ubuntu.
- [ ] **14. Services.** In waves. Before each wave the primary registers the wave's services in both crates and lands any shared model or quote and discovery code they need. One implementer and one worktree per service or slice, reads before writes, each write with adversarial review. A slice owns its service's paths in both crates as the [layout](../design/architecture.md#layout) lists them.
